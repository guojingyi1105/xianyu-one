# 极简耐看的开源 UI 素材库

仅在前端设计、原型或 UI 改造任务中读取。以下热度为 2026-09-19 调研快照；星数会变化，使用前以仓库当前许可证、版本和维护状态为准。

## 选择原则

1. 先识别现有框架、样式方案、组件库和设计令牌；已有成熟体系时优先延续。
2. 新项目选择一个主组件体系，最多补充一个无样式底座和一个图标库。不要混用多个有样式组件库。
3. “极简大气耐看”默认采用：中性底色、单一主色、有限字号、稳定间距、轻边框、少阴影、少渐变、清晰状态和克制动效。
4. 组件示例只作为结构素材。根据用户任务、真实内容和品牌重新设计层级、密度和令牌。
5. 安装或复制前检查当前许可证；保留依赖清单和适用的版权/许可证文本。不要从商业模板或许可证不清晰的社区 Registry 直接复制。
6. 添加依赖前说明收益、包体和维护代价；若原生 HTML/CSS 或现有组件足够，不新增库。

## 推荐目录

### shadcn/ui

- 仓库：https://github.com/shadcn-ui/ui
- 调研快照：约 123.5k stars，MIT。
- 特点：开放源代码分发模式，可直接拥有并改造组件源码；视觉中性，适合建立自己的设计系统。
- 优先场景：React、Next.js、Vite、Tailwind 项目；SaaS、设置页、表单、仪表盘和内部工具。
- 使用方式：先搜索现有组件与 Blocks，再组合页面；统一语义色、圆角、密度和排版，不堆叠 Card。
- 注意：复制源码意味着后续更新由项目自行维护；社区 Registry 必须单独审查来源和许可证。

### Radix Themes

- 仓库：https://github.com/radix-ui/themes
- 调研快照：约 8.7k stars，MIT。
- 特点：预制但克制的 React 组件与主题系统，重视可访问性和维护成本。
- 优先场景：需要快速得到稳定、统一、低噪声界面的 React 应用。
- 使用方式：减少强调色数量，使用主题令牌统一尺度；业务密集型页面保持适度紧凑。
- 注意：视觉定制度低于完全自定义方案，强品牌项目需要扩展主题而非叠加局部 CSS 补丁。

### Radix Primitives

- 仓库：https://github.com/radix-ui/primitives
- 调研快照：约 19.3k stars，MIT。
- 特点：无样式、可访问的底层交互组件，适合自建视觉系统。
- 优先场景：React 项目中的 Dialog、Popover、Tabs、Select 等复杂交互；需要高度定制且重视键盘和焦点行为。
- 使用方式：把它当交互底座，视觉完全服从项目令牌。
- 注意：不是开箱即用的视觉素材，需要自行完成样式、状态和响应式。

### Mantine

- 仓库：https://github.com/mantinedev/mantine
- 调研快照：约 31.7k stars，MIT。
- 特点：React 组件、表单、图表、通知、上传、编辑器等能力完整。
- 优先场景：复杂后台、运营工具、数据产品、表单密集型系统，希望减少自研组件成本。
- 使用方式：从中性主题开始，收紧色彩和阴影，统一表单高度与信息密度。
- 注意：能力较重；仅做少量页面时不要为了一个组件引入整套生态。

### Headless UI

- 仓库：https://github.com/tailwindlabs/headlessui
- 调研快照：约 28.7k stars，MIT。
- 特点：React/Vue 的无样式可访问组件，适合完全由用户定义视觉。
- 优先场景：已有 Tailwind 或自建设计系统，需要 Menu、Listbox、Dialog、Tabs 等可靠行为。
- 使用方式：保留其交互和可访问性语义，使用项目令牌完成视觉层。
- 注意：不是现成页面素材；必须自行补齐所有状态和布局。

### daisyUI

- 仓库：https://github.com/saadeghi/daisyui
- 调研快照：约 42k stars，MIT。
- 特点：基于 CSS 类、框架适配范围广，主题和组件覆盖丰富，原型速度快。
- 优先场景：快速 Demo、非 React 项目、对开发速度优先的轻量工具。
- 使用方式：选择或自建一个低饱和中性主题，删除多余主题和装饰，单独设计页面布局。
- 注意：直接使用默认主题容易显得模板化；正式产品需重新约束色彩、圆角、阴影和密度。复制样式片段时按 MIT 要求保留许可信息。

### Lucide

- 仓库：https://github.com/lucide-icons/lucide
- 调研快照：约 24.6k stars，ISC。
- 特点：统一、克制的线性 SVG 图标，支持多个前端框架和静态 SVG。
- 优先场景：按钮、导航、状态提示和操作图标。
- 使用方式：全产品统一线宽、尺寸和对齐；图标配文字优先，陌生的纯图标按钮必须有可访问名称和提示。
- 注意：不提供品牌 Logo；不要从其他来源混入不同笔画风格的图标。

## 场景路由

| 场景 | 推荐组合 |
|---|---|
| React/Tailwind 极简产品 | shadcn/ui + Lucide |
| React 快速构建且追求稳定一致 | Radix Themes + Lucide |
| 高度定制 React 设计系统 | Radix Primitives + Lucide |
| Vue/Tailwind 自定义界面 | Headless UI + Lucide |
| 复杂后台、表单和数据产品 | Mantine；图标优先沿用其生态或统一为 Lucide |
| 跨框架快速 Demo | daisyUI + Lucide |
| 已有组件库的存量项目 | 沿用现有库，仅从上述库借鉴结构与状态，不新增平行体系 |

## 素材采用流程

1. 根据页面任务列出所需组件和状态，不先逛库堆功能。
2. 从推荐目录选择一个主库，核对它是否支持当前框架和版本。
3. 查看官方组件、示例与源码，只选解决当前任务的部分。
4. 记录来源、许可证、安装方式和修改范围。
5. 将素材映射到设计决定单中的颜色、字体、间距、圆角、边框和动效。
6. 使用真实内容渲染桌面与移动视图，删除任何不服务任务的组件。
7. 向用户展示渲染图并说明借用了哪些素材、做了哪些定制。
