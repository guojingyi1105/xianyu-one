# Token 高效执行

用于大仓库、长任务、上下文受限或用户明确要求节约 token 的场景。目标是减少无关输入和重复输出，不是降低质量标准。

## 有依据的机制

- Aider 的 repo map 只把仓库中的关键符号、签名和相关片段放入活动 token 预算，并按依赖关系与当前任务选择重要内容。由此采用“先地图、后原文、按关系扩展”。
- Repomix 提供 include/ignore、token-count tree 与 Tree-sitter 压缩，说明上下文应先选择范围、查看 token 分布，再决定是否压缩；压缩内容不能替代需要编辑或审查的原文。
- AGENTS.md 约定让根规则只保存全局事实，子目录仅补充局部差异，不重复祖先规则。由此采用“分层指令、就近覆盖、避免复述”。
- GitHub Spec Kit 将 specify/plan/tasks/implement 作为核心过程，把 clarify/checklist/analyze 用作存在实质歧义时的质量门；其现有项目指南也反对一开始为整个旧系统补文档。由此采用“按风险启用产物与门禁”。
- Agent Skills 的公开 skill-creator 把元数据、主 SKILL 与按需资源分成三个加载层级。由此让主文件只负责路由和不可省略规则，细节保留在 references。

来源与取舍记录保存在公开仓库的 `docs/research-basis.md`，不纳入运行时 Skill 包；执行本流程不需要加载该维护文档。

## 上下文阶梯

按下列层级逐步扩展，一层已足以作出可靠决定就停止：

1. 用户请求、当前约束、仓库级指令和工作区状态。
2. 目录树、文件名、搜索命中、符号或接口摘要。
3. 将要修改的目标文件原文。
4. 直接调用方、被调用接口、相邻测试、配置与数据契约。
5. 只有跨域改造、发布或证据冲突时才读取更广范围。

禁止把依赖目录、构建产物、二进制、生成文件、锁文件全文或无关历史默认送入上下文。若工具可用，优先使用仓库地图、token 分布、include/ignore 或符号索引；涉及秘密时保留安全扫描和忽略规则。

## 任务规模与产物

| 规模 | 默认产物 | 何时升级 |
|---|---|---|
| S：单点、低风险、验收明确 | 一段变更契约 + 定向验证 | 发现跨模块影响、安全或数据风险 |
| M：跨文件/跨层、存在取舍 | 产品摘要 + 任务清单 + 验收矩阵 | 关键歧义未解或需长期架构决定 |
| L：新产品、跨系统、上线 | 产品契约 + 轻量规格 + 架构/任务/发布门禁 | 不再继续扩张；按能力引用专门资料 |

不要为了形式完整生成空洞 PRD、ADR、全量测试计划或重复清单。需要长期保留且影响多个后续决策时才写 ADR；需要用户选择时才进入访谈；需要真实发布时才运行发布门禁。

## 工作记忆

长任务维护一个紧凑状态块，更新而非追加重复版本：

```text
目标：
范围 / 非目标：
已确认事实：
未决风险：
当前改动：
下一验证：
```

用户可见更新只报告自上次以来的新增证据、改变的决定、阻塞与下一步。不要反复复述背景、完整计划或已经通过的检查。

## 验证阶梯

1. 格式、类型或静态检查，限定到改动文件或包。
2. 与变更直接相关的单元/契约测试。
3. 受影响模块的集成、构建或真实样本。
4. 跨层、共享基础设施或发布任务再扩展到全量回归、端到端、视觉与发布门禁。

若定向检查失败，先修复或解释，再扩展范围；不要用重复全量运行替代定位。若变更影响共享配置、公共 API、数据库迁移、权限或安全边界，不得仅以定向测试宣告完成。

## 停止与再加载

- 同一文件在未变化且没有新问题时不重复读取。
- 搜索结果连续不改变方案、风险或验收时停止搜索。
- 压缩摘要与原文冲突时，以当前原文为准并刷新摘要。
- 上下文压缩后只恢复当前目标、已确认决定、变更集、未决风险和下一验证；不要恢复全部对话。
- 用户要求完整审计、法律/安全/财务高风险或证据不足时，质量优先于 token 预算。
